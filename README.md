# Visa Routes

Which work visa routes can an international graduate actually use, and what does each one require?

You answer a few questions about yourself. For each destination, every work visa route is marked
**open**, **depends on an employer** or **closed**, with one sentence saying why and a checklist split
into what you can check now, what to ask the employer, and what the authority decides. Every line
quotes an official government page, links to it, and shows the date a person last read the rule
against it.

It is built for people of many nationalities rather than one, and it is information rather than legal
advice.

## How it works

Three principles decide most of the design.

**Deterministic rules, never a model.** No language model states a visa fact to a user. Rules live as
data in `src/data/`, evaluated by a small engine in `src/engine/`. Models help with research; a person
verifies. Visa rules are exactly the kind of near-source text where automated checkers quietly distort
a number or drop a hedge.

**Official sources only, quoted verbatim.** Every requirement carries the wording it came from, its
publisher, its URL and the date it was fetched. Law-firm guides, forums and news articles are leads
for finding a rule, never citations for one. A weekly job re-fetches every page and opens an issue if
a quote is no longer there.

**Retrieved and verified are different words.** *Retrieved* is when a script last fetched the page.
*Verified* is when a person read the rule against that page and approved it. A route that nobody has
verified says so, on the card. Claiming otherwise is the worst bug this project could have, so the
two are kept apart everywhere.

**Nothing about you is stored.** There is no backend, no database and no account. Your answers live in
the URL, which is also what makes a result shareable.

## Contributing

The most useful contribution is **a rule that is wrong**, with the official page that proves it. There
is an issue template for exactly that, and it needs no setup.

[CONTRIBUTING.md](CONTRIBUTING.md) has the rules that make this project work, and they are stricter
than most: every rule needs a verbatim quote from an official page, quotes are copied from a saved
snapshot rather than from any model or summary, non-English quotes carry a literal translation, and
nobody sets `verified` in a pull request.

## Development

```sh
git clone https://github.com/Metry630/visa-navigator.git
cd visa-navigator
npm install
npm run dev
```

```sh
npm test               # engine tests
npm run typecheck
npm run lint
npm run check:data     # schema, grounding and verification report for src/data
npm run check:sources  # re-fetch every page and confirm each quote is still on it
npm run review         # the local review page, the only thing that may write `verified`
```

Adding a dependency needs `bun`, not npm: `bun.lock` is the committed lockfile and npm does not update
it, so CI would fail its install step.

The UI is built through [Lovable](https://lovable.dev), which commits to `main` directly. The engine,
the data, the scripts and CI are not, and `CLAUDE.md` records which side owns what.
